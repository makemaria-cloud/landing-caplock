4. Проверить HTTPS, доступность политики, согласие и форму. По отдельному

## Продолжение На Новом Устройстве

Для новой локальной копии:

```sh
git clone https://github.com/makemaria-cloud/landing-caplock.git
cd landing-caplock
```

Для существующей копии сначала проверить `git status`, сохранить свои
изменения, затем обновить через `git pull --ff-only`. Не использовать
`reset --hard`, force push или безусловное удаление файлов.

Для просмотра достаточно открыть `index.html`. Для работы формы нужны
серверная среда и приватные настройки. Для серверных тестов нужны PHP 8.2+
с curl/openssl/fileinfo/mbstring и зависимости из `server/composer.lock`:

```sh
composer install --working-dir=server --no-dev
php tests/server.php
```

Браузерные тесты используют Python 3.10+, Playwright и локальный PHP:

```sh
python -m pip install -r tests/requirements-browser.txt
python tests/browser.py --php php --browser-channel msedge
```

На Windows можно передать абсолютный путь к `php.exe`. Для установленного
Chrome выбрать `--browser-channel chrome`. Если нет обоих браузеров,
выполнить `python -m playwright install chromium` и выбрать
`--browser-channel chromium`. Тесты сами запускают и останавливают локальный
сервер, блокируют внешние запросы, используют фиктивные данные и сохраняют
результаты в игнорируемой Git папке `test-results/browser/`.

Авторизация GitHub, PHP/Python и зависимости на другое устройство через Git
не переносятся: установить/авторизовать заново. Для public clone вход не нужен,
для push нужен доступ к репозиторию. После каждого обновления обязательны
русский коммит, push и сверка локального и удаленного хешей.

## Ограничения И Безопасность

- Репозиторий содержит код и несекретные инструкции, не полную копию аккаунта
  Hostland. Приватного рабочего конфига и реальных клиентских заявок у нас нет.
- Не присылать пароли, SSH-ключи и URL вебхука в чат. Не добавлять в публичный
  GitHub конфиги, очереди, логи, файлы клиентов, дампы БД или выгрузки 1С/Битрикс.
- `vendor/` устанавливается Composer, не хранится в Git. Локальные инструменты,
  старые скриншоты и диагностические папки не являются зависимостями проекта.
- Очистка очереди, ручной контроль ошибок/неизвестной доставки и ограничения
  файлов описаны в README_DEPLOY.md. Нет автоматического мониторинга доставки;
  MIME/сигнатуры не заменяют антивирус, сроки в CRM и почте контролирует оператор.
- Старая мобильная панель имеет отдельное замечание на узком экране из аудита;
  не считать все замечания запуска устраненными только из-за успешных тестов.
