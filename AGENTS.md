# Правила для всех исполнителей

Перед работой прочитать [CODING_RULES.md](CODING_RULES.md) и
[CONSULTANT_RULES.md](CONSULTANT_RULES.md). Они действуют во всем репозитории.

## Обязательный коммит и push

После каждого завершенного обновления кода, изображений, настроек,
документации, правил или отчетов обязательно:

1. Выполнить применимые проверки и просмотреть изменения.
2. Проверить, что в коммит не попадают секреты, клиентские данные и посторонние файлы.
3. Сделать коммит с понятным сообщением на русском языке.
4. Выполнить push в текущую рабочую ветку `origin` без отдельного напоминания.
5. Сверить локальный и удаленный хеши и передать владельцу ссылку на коммит.

Обновление без успешного push не считается полностью сданным. Если отправка
не удалась, явно сообщить причину, не скрывать ошибку и не заявлять об успехе.
При отсутствии изменений пустой коммит не нужен. Команды Git не переводятся;
сообщения коммитов и итоговые отчеты пишутся на русском языке.

Не использовать force push и не переписывать чужую историю без отдельного
прямого разрешения владельца. Не отправлять данные из соседних папок рабочего
компьютера. Этот репозиторий содержит только лендинг CUP-LOCK и его документацию.

## Границы работы

- Сохранять текущие тексты и оформление, если задача не требует их изменения.
- Не выдавать демонстрационную форму за работающий прием заявок.
- Отправка кода в GitHub не означает размещение сайта на хостинге.
- Публикация сайта, подключение CRM, аналитики и обработчиков заявок требуют отдельной задачи.
- Соблюдать распределение ролей консультанта и кодера из соответствующих правил.
