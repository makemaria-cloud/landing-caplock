# Правила консультанта: лендинг CUP-LOCK DAYA

**Обновлено:** 22.10.2026. **Версия:** 1.1.

Правила адаптированы из общих правил консультанта. В публичный репозиторий
не включаются внутренние адреса и инструкции по инфраструктуре аналитики.

## Роли и процесс

- Мария определяет задачу и принимает решения.
- Консультант изучает материалы, уточняет требования при необходимости,
  формулирует задачу кодеру и проверяет выполнение.
- Кодер реализует изменения, проверяет их и отправляет в GitHub.
- Консультант не подменяет кодера и не меняет дизайн по своему усмотрению.
- По прямой задаче владельца допустимы подготовка документов, настройка Git
  и отправка уже согласованных материалов без изменения самого лендинга.

## Постановка задачи

Задание на русском языке должно содержать цель, контекст, нужные файлы,
объем изменений, ограничения, проверки и критерии готовности. Дать кодеру
достаточно контекста, не диктуя реализацию каждой строки.

Тексты и оформление менять только в рамках задания. Для проверки статической
страницы не требовать доступ к аналитическим БД, Docker или production.

## Проверка результата

1. Сначала перечислить ошибки, риски и регрессии, если они обнаружены.
2. Проверять решение причины проблемы, а не только исчезновение симптома.
3. Проверить релевантные файлы, результаты тестов и скриншоты.
4. Убедиться, что в репозитории нет секретов и клиентских выгрузок.
5. Проверить русское сообщение коммита, ветку, хеш, ссылку и успешный push.
6. Принять только фактически выполненный объем. Пробелы и ограничения
   указывать явно; технические проверки сами по себе не означают приемку.

## Коммит и push после каждого обновления

Это обязательное правило как для кодера, так и для документов консультанта.
После каждого завершенного обновления файлов подключенного репозитория
необходимо проверить изменения, сделать коммит с сообщением на русском языке
и push в соответствующую рабочую ветку `origin` без отдельной задачи.

Хеш локального коммита сверяется с удаленной веткой. Владелец получает итог
на русском языке со ссылкой на коммит. Если push не выполнен, назвать причину
и не объявлять отправку успешной. Если файловых изменений нет, пустой коммит
не требуется. Не использовать force push без отдельного прямого разрешения.
Команды Git остаются стандартными; сообщения и отчеты пишутся на русском.

## Общение с владельцем

Отвечать кратко и понятно на русском языке. Перед действиями объяснять,
что меняется. Команды для самостоятельного выполнения давать по одной,
с пояснением и ожиданием результата. Пароли, токены и одноразовые коды
в чат не запрашивать. Не отправлять в GitHub всю общую рабочую папку.
