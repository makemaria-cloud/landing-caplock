## Раскладка файлов

Пример, не готовые пути вашего аккаунта:

```text
/home/ACCOUNT/caplock-public/        <- document root поддомена
  index.html, style.css, form-state.css, app.js, form-utils.js, lead-form.js
  assets/
  api/lead.php
/home/ACCOUNT/caplock-private/       <- недоступно через HTTP
  caplock.config.php
  app/                             <- содержимое server/, включая vendor/
  queue/                           <- запись разрешена только PHP аккаунта
```

Не загружать в document root приватный конфиг, очередь, `server/`, `tests/`,
`.git/`, отчеты и задания. `.htaccess` в исходниках — дополнительная защита,
не замена приватной папке: нельзя полагаться на его поддержку веб-сервером.

1. В приватной `app/` установить зависимости командой
   `composer install --no-dev --prefer-dist --classmap-authoritative`
   из имеющегося `composer.lock`. Если Composer на хостинге недоступен,
   собрать зависимости в доверенной среде PHP и загрузить `vendor/` приватно.
2. Скопировать `config.example.php` в приватный `caplock.config.php`.
   Заполнить абсолютные `document_root`, `storage` и все CRM/SMTP-параметры.
   `rate_key` сгенерировать случайно (`bin2hex(random_bytes(32))`).
3. Настроить переменные окружения веб-процесса PHP:
   `CAPLOCK_APP=/home/ACCOUNT/caplock-private/app` и
   `CAPLOCK_CONFIG=/home/ACCOUNT/caplock-private/caplock.config.php`.
   Способ зависит от режима PHP в Hostland: подтвердить его в панели или
   поддержке. Не подставлять секреты в HTML, JavaScript или публичный PHP.
4. Выдать приватным каталогам права 0700, конфигу и файлам очереди 0600.
   На аккаунтах с иной моделью владельцев согласовать эквивалентные права.
5. Проверить расширения PHP: curl, openssl, fileinfo, mbstring, session;
   запись приватной очереди и сессий, корневые сертификаты, доступ к порту
   8443 CRM и SMTP. На поддомене `$_SERVER['HTTPS']` должен иметь значение `on`.
6. Установить `upload_max_filesize=20M`, `post_max_size=27M`,
   `max_file_uploads=5`, `memory_limit=256M` или выше. Также согласовать
   лимит тела запроса веб-сервера. Сам обработчик отклоняет тело более 26 MiB.
7. Настроить HTTP -> HTTPS на веб-сервере и корректный сертификат поддомена.
8. Только после согласования согласия указать `consent_text`, установить
   `consent_approved=true`, затем `enabled=true`. До этого GET/POST формы
   отвечают 503 и не принимают персональные данные в очередь.

Поле города передается строкой в **`UF_CRM_1667293827361`** — «Адрес (DaData)»
именно лида. Это не вызов сервиса DaData, не проверка адреса и не геокодирование.
Код и ID сотрудника найдены в локальной выгрузке; актуальность в живом портале
проверить перед включением. Не использовать код адреса сделки вместо лида.

## Очередь и контроль доставки

Cron каждую минуту, с реальным путем CLI PHP соответствующей версии:

```sh
CAPLOCK_CONFIG=/home/ACCOUNT/caplock-private/caplock.config.php /path/to/php /home/ACCOUNT/caplock-private/app/worker.php run
```

Крон должен работать от того же пользователя, что и прием заявок.
Вывод и ошибки сохранять только приватно; путь CLI PHP уточнить в Hostland.
Статус без персональных данных: та же команда с `status` вместо `run`.

- HTTP 202 означает устойчивый прием в очередь, а не доставку.
- Каналы `crm`, `email`, `crm_comment` обрабатываются отдельно.
- `retry` повторяется с задержкой, максимум пять попыток; `failed` требует
  вмешательства. `uncertain` означает неизвестный итог после начала отправки:
  слепого повтора нет. Восстановление только после проверки CRM по номеру
  заявки / техническому полю и почты по номеру и Message-ID.
- Не обещается exactly-once: получатель SMTP может принять письмо без
  полученного сервером подтверждения. После неопределенного ответа прием
  повторяют с тем же номером и теми же данными, без создания нового лида.
- Ежедневно проверять cron, статусы ошибок и свободное место. Полноценного
  автоматического мониторинга/оповещения администратора пока нет.
- Через 7 дней cron удаляет содержимое заявки и файлы, в том числе при
  незавершенной доставке. До 30 дней остается технический след для защиты
  от повторов. Ошибки нужно разобрать **до** срока очистки. Без cron очистка
  не выполняется; очередь ограничена 500 техническими записями.

Вложения хранятся приватно, отправляются в письмо и поле CRM. Ссылки на файлы
для комментария извлекаются из CRM через `crm.lead.get`, допускаются только
без секретов на согласованном портале. Если формат ответа другой, остается
явно обозначенная ссылка на карточку, а в результате `crm_comment` — флаг
`fallback`: это ограничение, а не подтвержденная прямая ссылка на файл.
Доступ менеджера к ссылкам и корректное отображение проверить на живом тесте.
Комментарий прочитывается перед дополнением; одновременная правка менеджером
между чтением и записью не защищена транзакцией API.

До 5 файлов, 20 MiB каждый, 25 MiB суммарно: PDF/DWG/DXF/XLS/XLSX/DOCX/ZIP.
Проверяются расширения, MIME и сигнатуры, но это **не антивирусная проверка**.
Архивы не распаковываются. Большие комплекты передавать ссылкой на проект;
обработчик не скачивает внешние ссылки. Прием документов и защиту рабочих
мест менеджеров от вредоносных вложений согласовать перед запуском.

## Приемочный тест

Сначала локально: `php tests/server.php` с указанными расширениями PHP.
После развертывания отдельно согласовать одну реальную тестовую заявку:
телефон/email/город/комментарий, PDF и UTM. Проверить ответственного,
поле Dadata, файлы и ссылки в CRM, доставку письма с вложением, статусы
очереди и отсутствие дубля при повторной отправке. Только затем запускать
рекламу. Настоящих заявок в ходе разработки не отправляли.
